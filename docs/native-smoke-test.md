# قائمة الاختبار اليدوي للأجهزة

هذه القائمة مخصصة للتحقق النهائي من الميزات التي لا يمكن محاكاتها بدقة في بيئة الويب أو اختبارات Vitest. لا تضيف أي ميزة إلى التطبيق؛ هي مرجع قصير قبل مشاركة النسخة مع الأسرة.

## شروط الاختبار

استخدم جهاز iOS وجهاز Android إن أمكن، وابدأ ببيانات اختبار غير حساسة. تحقق من منح الصلاحيات ورفضها مرة واحدة على الأقل، ثم احذف بيانات الاختبار بعد الانتهاء.

| المسار | الخطوات | النتيجة المتوقعة |
|---|---|---|
| الكاميرا | افتح ملف فرد، اختر التقاط صورة، اسمح بالكاميرا، التقط صورة، عاينها، ثم اعتمدها أو أعد الالتقاط. | تظهر المعاينة، تُحفظ الصورة المضغوطة، ويظل الرمز الافتراضي آمنًا عند الرفض أو الإلغاء. |
| البصمة أو Face ID | فعّل قفل التطبيق، اقفل التطبيق وافتحه، ثم اختبر نجاح المصادقة وفشلها أو إلغائها. | لا تُعرض البيانات قبل المصادقة، وتظهر رسالة واضحة عند الرفض دون فقد البيانات. |
| الإشعارات | فعّل إشعار الملخص الأسبوعي، اختر اليوم والوقت، ثم عطّله وأعد تفعيله. | تُطلب الصلاحية بلطف، تُجدول الإشعارات أو تُلغى، ولا يحدث تكرار غير مقصود. |
| المناسبات | أضف مناسبة بتذكير، تحقق من وقتها، ثم عدّلها واحذفها. | تُحفظ التغييرات محليًا ويُحذف التذكير المرتبط عند حذف المناسبة. |
| المشاركة وPDF | أنشئ تقريرًا، شاركه، ثم نزّله أو احفظه. | يفتح ملف PDF صالحًا، وتظهر ورقة المشاركة أو رسالة مناسبة إذا لم يدعم النظام الإجراء. |
| النسخة الاحتياطية | أنشئ نسخة مشفّرة، أغلق التطبيق، ثم استعدها بكلمة صحيحة وبكلمة خاطئة. | تظهر معاينة قبل الاستبدال، تنجح الاستعادة الصحيحة، ولا تتغير البيانات عند كلمة خاطئة. |

## معايير النجاح

يُعد المسار ناجحًا إذا لم يتوقف التطبيق أو يفقد بيانات محلية، وكانت الرسائل مفهومة بالعربية، وعاد المستخدم إلى الشاشة السابقة دون حالة معلقة. سجّل نوع الجهاز ونظام التشغيل وأي خطوة فشلت مع وصف مختصر، ولا تُرفق بيانات عائلية حقيقية عند الإبلاغ عن المشكلة.

## ما تم التحقق منه آليًا مسبقًا

تم التحقق من مسارات التطبيق عبر تصدير Expo للويب، ومن إعدادات iOS وAndroid، ومن TypeScript وVitest وlint. هذه القائمة تغطي فقط الأجزاء التي تعتمد على نظام التشغيل أو عتاد الجهاز، ولا تستبدل الاختبارات الآلية.
